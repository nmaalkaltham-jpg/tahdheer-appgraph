Inheritance: global → category term meta → product post meta. Resolve with a single tahdheer_pdp_config( $product_id ) that merges the three layers once per request and caches on the product id. Every renderer reads that one array — no renderer calls get_option() directly.

5.1 · Preset 0 is the existing output — the reversibility contract

This is an upgrade, not a replacement. The theme's current product-info output is registered as preset 0 «الأصلي» and is the default fallback, so the new engine is a reversible layer rather than a migration. Concretely, preset 0 reproduces exactly what ships today:

Current outputEmitted byPreserved as
.tahdheer-buy-trusttahdheer_single_buy_trust() @ 35Preset 0 body — 13px/700 muted text, 19px green icons, 12/22px gaps, 18px top rule. Unchanged CSS.
.tah-sales-rowtahdheer_single_sales_count()Preset 0 pill — including the --hot gold variant and the Arabic count pluralisation.
✓
{{ r.title }}{{ r.body }}

Storage shape. Nothing overwrites the legacy path: tahdheer_pdp[preset] holds the active preset id (default 0), tahdheer_pdp[preset_settings][<id>] holds each preset's own appearance bucket, and tahdheer_pdp[facts] holds the ordered fact instances. Switching presets writes only preset; the other buckets are untouched, which is what makes a round-trip lossless. When preset = 0 the new renderer short-circuits and the existing hooks emit as before — so an uninstalled or errored engine degrades to today's page, not a blank one.

Adding Style 11 is one entry in the preset registry plus one <sc-if> branch in the renderer. Data, settings resolution, accessibility, responsive and motion are shared — presentation is the only layer that varies.

5.3 · Purchase bar + share actions

Both ship as reversible layers with Original as the default, so installing changes nothing until a mode is switched. tahdheer_pdp[purchase_mode] = original | sticky and tahdheer_pdp[share_mode] = original | row | floating | expandable. Choosing Original restores the existing markup and behaviour exactly — the old CTA and sticky-bar code is never deleted, only branched around.

ItemBehaviourImplementation note
Duplicate mobile CTA2 → 1 add-to-cartSticky mode hides the inline CTA row on mobile only; desktop keeps it. Verified 2→1→2 on revert.
Safe areaiPhone home barcalc(12px + env(safe-area-inset-bottom)) on the bar's outer padding.

Variations & quantity. Buy Now must submit the same form the inline CTA does — carrying variation_id, quantity and any required attributes — not a bare product-id link, or variable products silently add the wrong item. Disable Buy Now until a variation is chosen, mirroring WooCommerce's own add-to-cart gating. Sticky-UI collision: the bar publishes its height as --tah-purchase-bar-h so a cookie bar or chat bubble can offset itself instead of overlapping.
