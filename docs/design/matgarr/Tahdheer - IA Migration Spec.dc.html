4 · Section order — from hard-coded to stored

Today front-page.php fixes the order in PHP: hero → features-bar → stage-cards → best-sellers → home-widgets. The Section Manager needs the order in a setting so it can be dragged.

tahdheer_home_order = ["hero","trust","stages","featured","subjects", "best","promo","why","reviews","faq","cta"]

Migration (idempotent): on first read, if tahdheer_home_order is unset, seed it from the current hard-coded order and persist. front-page.php then loops the array and calls get_template_part() per id, checked by the existing tahdheer_feature_enabled() checks — so the existing enable_* flags keep working unchanged. Unknown ids in the array are skipped; ids missing from the array are appended at the end, so a theme update that adds a section can never drop it.

Widgets inserted between sections are stored as "widget:home-widgets:3" entries in the same array, which is what makes “+ add a section or widget here” land where the user pointed instead of falling into the footer.
