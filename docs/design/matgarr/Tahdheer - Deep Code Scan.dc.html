الشكل الصحيح ليس الثقة بترويسة X-Forwarded-For — ذلك يفتح تزييف حدّ المعدّل. الشكل الصحيح: قائمة بيضاء لعناوين وسطائك الموثوقين، ولا تُقرأ الترويسة إلا إذا كان REMOTE_ADDR واحدًا منها، ثم يُؤخذ آخر عنوان غير موثوق في السلسلة.

function tahdheer_client_ip() {
  $remote = filter_var( $_SERVER['REMOTE_ADDR'] ?? '', FILTER_VALIDATE_IP );
  if ( ! $remote ) { return 'unknown'; }

  /** قائمة بيضاء لوسطاء موثوقين — فارغة افتراضيًا = السلوك الحالي بالحرف. */
  $trusted = (array) apply_filters( 'tahdheer_trusted_proxies', array() );
  if ( ! in_array( $remote, $trusted, true ) ) { return $remote; }

  $chain = explode( ',', (string) ( $_SERVER['HTTP_X_FORWARDED_FOR'] ?? '' ) );
  foreach ( array_reverse( $chain ) as $hop ) {
    $ip = filter_var( trim( $hop ), FILTER_VALIDATE_IP );
    if ( $ip && ! in_array( $ip, $trusted, true ) ) { return $ip; }
  }
  return $remote;
}

الفلتر فارغ افتراضيًا، أي أن تطبيق الرقعة وحدها لا يغيّر شيئًا — السلوك يتغيّر فقط عند تعبئة القائمة بعنوان وسيطك. هذا يجعلها آمنة للنشر قبل معرفة بنيتك.

سؤال واحد يحسم الرقعة الثانية

هل الموقع خلف Cloudflare أو موازن حِمل أو أي بروكسي؟ إن كان الجواب نعم، فحدّ المعدّل على الدخول والـOTP اليوم يعمل على عدّاد واحد لكل زوّار الموقع — ‎١٢ محاولة دخول كل ‎١٥ دقيقة للجميع مجتمعين، و‎OTP واحد لكل ساعة للجميع. وهذا يقفل عملاء شرعيين في أوقات الذروة. إن كان الجواب لا، فالشيفرة الحالية صحيحة تمامًا ولا تُلمس.
